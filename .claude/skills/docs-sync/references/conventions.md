# docs-zip 문서 컨벤션

이 저장소의 기존 디렉터리(`claude-code/`, `codex/`, `openrouter/`)에서 관찰되는 실제 컨벤션이다. 새 문서는 이를 따르고, 기존 문서를 수정할 때는 그 디렉터리의 기존 스타일을 우선한다.

## 디렉터리 구조

```
docs-zip/
├── <product>/              # 제품/프로젝트당 하나의 최상위 디렉터리 (kebab-case)
│   ├── README.md           # 인덱스 (모든 디렉터리에 두는 것이 정책)
│   ├── 00-overview.md      # 번호 prefix 문서들
│   ├── 01-installation.md
│   └── ...
```

## 파일명 규칙

- `NN-kebab-case-topic.md` — 두 자리 번호 prefix + 영문 kebab-case 주제명
- 신규 디렉터리는 `00-overview.md`부터 시작한다. (기존 디렉터리가 `01-`부터 시작하면 그 체계를 유지)
- 번호는 대략적 학습 순서: overview → installation → reference류 → 기능별 → 보안/정책 → 모범 사례
- **기존 파일의 번호는 변경하지 않는다.** 신규 문서는 마지막 번호 뒤에 추가한다. 번호 순서와 주제 분류가 어긋나도 README 인덱스가 카테고리로 묶어주므로 문제없다.

## 문서 구조

```markdown
# <제품명> <주제>                          ← H1 하나. 제품명 + 주제

> 원문: https://...                        ← 인용구로 원문 URL (대조 기준이 되므로 필수)

한두 문단의 주제 개요.                      ← 무엇이고 왜 쓰는지

---

## 섹션 제목                               ← `---` 로 큰 섹션 구분

| 항목 | 설명 |                            ← 표 중심 정리 (이 저장소의 핵심 스타일)
| --- | --- |

### 하위 섹션

```python / ```typescript / ```shell      ← 코드 예제. API류는 Python + TypeScript 병기
```

핵심 원칙:

- **언어**: 한국어. 기술 용어, 명령어, 파라미터명, 코드 식별자는 원문 유지 (예: "스트리밍을 지원합니다", `stream: true`)
- **원문 링크**: 문서 상단 인용구에 반드시 기록. 여러 페이지를 합친 문서면 주요 페이지를 모두 나열하거나 섹션별로 표기. 다음 동기화 때 이 링크가 대조 기준이 된다.
- **표 우선**: 옵션·파라미터·비교는 산문보다 표로. 산문은 개념 설명에만.
- **코드 예제**: 공식 문서의 예제를 기반으로 하되, placeholder는 `<YOUR_API_KEY>` 형식 통일.
- **굵기**: 문서 하나는 공식 문서의 주제 단위(설치, CLI 레퍼런스, 설정, 훅, MCP, 보안 등) 하나에 대응. 공식 페이지 여러 개를 합쳐도 되지만, 한 문서가 800줄을 크게 넘으면 분할을 고려.
- **beta/deprecated 표기**: 공식 문서의 표기를 그대로 반영 (예: "Server Tools (Beta)").

## README.md 인덱스 템플릿

`openrouter/README.md`가 표준형이다. 구조:

```markdown
# <제품명> 개발자 문서

> <제품 공식 문서 URL>를 기반으로 정리한 한국어 개발자 가이드입니다.
> 최종 업데이트: YYYY-MM-DD                ← 동기화 실행일로 갱신

<제품 한 문단 소개>

---

## 문서 목록

### <카테고리>                             ← 기본 / 핵심 기능 / 통합 / 정책 등 주제별 그룹

| # | 문서 | 설명 |
| --- | --- | --- |
| 01 | [문서 제목](./01-xxx.md) | 핵심 키워드 나열형 한 줄 설명 |

---

## 빠른 참조                               ← 엔드포인트 표, 핵심 명령어, 설정 스니펫 등
                                            제품에서 가장 자주 찾게 되는 것들

---

## 원문 링크

- 공식 문서: https://...
- (모델 목록, API 상태, GitHub 등 보조 링크)
```

- 문서 표의 `#`는 파일 번호. 카테고리 안에서는 번호가 비순차여도 된다(카테고리가 우선).
- "최종 업데이트" 날짜는 메인 루프가 전달한 오늘 날짜를 쓴다 (Workflow 스크립트 안에서는 Date 사용 불가).

## 커밋 컨벤션

- 한글 커밋 메시지, git convention prefix (`docs:`, `fix:`, `chore:` 등)
- 작업 유형별로 논리 단위 분리 커밋, 각 커밋 후 push
- 실제 이력에서 가져온 표준 패턴:

| 작업 | 커밋 메시지 패턴 |
| --- | --- |
| 신규 문서 추가 | `docs: <제품> 공식 문서 전수조사 - 신규 문서 N개 추가` |
| 기존 문서 수정 | `fix: 기존 <제품> 문서 N개 수정 - 공식 문서 대조 결과 반영` |
| 문서 삭제 | `docs: <제품> 폐기 문서 N개 삭제 - 공식 문서에서 제거된 기능` |
| 인덱스 갱신 | `docs: README 인덱스 업데이트 - 신규 문서 및 섹션 반영` |
| 신규 디렉터리 전체 | `docs: <제품> 공식 문서 전수조사 - 문서 세트 신규 작성 (N개)` |

- git merge / rebase는 절대 수행하지 않는다 (사용자 글로벌 규칙).
