## 서브에이전트 개요

서브에이전트(Subagent)는 Claude Code에서 특정 작업에 특화된 AI 어시스턴트입니다. 메인 대화와 **분리된 컨텍스트 윈도우**에서 동작하며, 작업이 끝나면 결과만 메인 대화로 반환합니다.

### 핵심 특징

| 특징 | 설명 |
|------|------|
| **특화된 목적** | 각 서브에이전트는 명확한 단일 역할을 수행 |
| **독립 컨텍스트** | 메인 대화와 분리된 자체 컨텍스트 윈도우 사용 |
| **도구 제어** | 서브에이전트가 사용할 수 있는 도구를 제한 가능 |
| **커스텀 프롬프트** | 역할에 맞는 시스템 프롬프트로 행동 가이드 |

### 작동 방식

```
사용자 요청 → Claude Code → 적절한 서브에이전트에 작업 위임
                                ↓
                    서브에이전트가 독립 컨텍스트에서 작업 수행
                                ↓
                    결과를 메인 대화로 반환
```

## 파일 위치

서브에이전트는 마크다운 파일로 정의되며, 두 가지 위치에 저장할 수 있습니다.

| 유형 | 위치 | 범위 | 우선순위 |
|------|------|------|----------|
| **프로젝트 서브에이전트** | `.claude/agents/` | 현재 프로젝트에서만 사용 가능 | **높음** |
| **사용자 서브에이전트** | `~/.claude/agents/` | 모든 프로젝트에서 사용 가능 | 낮음 |

이름이 충돌하는 경우 프로젝트 레벨 서브에이전트가 사용자 레벨보다 우선합니다.

---

## 파일 형식

서브에이전트는 **YAML frontmatter + 마크다운** 형식으로 정의합니다.

```markdown
---
name: your-sub-agent-name
description: 이 서브에이전트가 언제 호출되어야 하는지에 대한 설명
tools: tool1, tool2, tool3  # 선택 - 생략시 모든 도구 상속
model: sonnet               # 선택 - 모델 별칭 또는 'inherit'
---

서브에이전트의 시스템 프롬프트가 여기에 들어갑니다.
역할, 능력, 문제 해결 방식을 명확히 정의하세요.

구체적인 지침, 모범 사례, 제약사항을 포함하세요.
```

## Frontmatter 필드

| 필드 | 필수 | 설명 |
|------|------|------|
| `name` | **예** | 소문자와 하이픈을 사용한 고유 식별자 |
| `description` | **예** | 서브에이전트의 목적을 설명하는 자연어 설명 |
| `tools` | 아니오 | 쉼표로 구분된 도구 목록. 생략시 메인 스레드의 모든 도구 상속 (MCP 도구 포함) |
| `model` | 아니오 | 사용할 모델. `sonnet`, `opus`, `haiku` 중 하나 또는 `'inherit'`. 생략시 기본값 `sonnet` |
| `permissionMode` | 아니오 | 권한 모드 설정 |
| `skills` | 아니오 | 자동 로드할 스킬 목록 |

### 모델 선택 가이드

| 설정 | 설명 |
|------|------|
| `sonnet` | 빠르고 효율적인 기본 모델 |
| `opus` | 복잡한 분석과 심도 있는 작업에 적합 |
| `haiku` | 가볍고 빠른 탐색 작업에 적합 |
| `inherit` | 메인 대화와 동일한 모델 사용 (일관성 보장) |
| _(생략)_ | 기본 서브에이전트 모델 사용 (`sonnet`) |

### 도구 설정

```yaml
# 방법 1: tools 필드 생략 → 모든 도구 상속
---
name: general-helper
description: 범용 도우미
---
# 모든 도구 사용 가능

# 방법 2: 특정 도구만 지정
---
name: read-only-reviewer
description: 읽기 전용 리뷰어
tools: Read, Grep, Glob, Bash
---
# 지정된 도구만 사용 가능
```

## CLI를 통한 동적 정의

CLI를 통해 JSON 형식으로 서브에이전트를 동적으로 정의할 수 있습니다. `--agents` 플래그를 사용합니다.

```bash
claude --agents '[
  {
    "name": "security-reviewer",
    "description": "보안 전문가 리뷰어",
    "model": "opus",
    "tools": ["Read", "Grep", "Glob"]
  }
]'
```

## 빌트인 서브에이전트

Claude Code에는 3가지 빌트인 서브에이전트가 내장되어 있습니다.

### 1. General-purpose (범용)

| 항목 | 값 |
|------|-----|
| **모델** | Sonnet |
| **도구** | 전체 도구 접근 |
| **권한** | 읽기/쓰기 모두 가능 |
| **용도** | 일반적인 코딩 작업, 파일 수정, 명령 실행 |

### 2. Plan (계획)

| 항목 | 값 |
|------|-----|
| **모델** | Sonnet |
| **도구** | 읽기 전용 탐색 도구 |
| **권한** | 읽기 전용 |
| **용도** | 코드 분석, 아키텍처 검토, 구조 파악 |

### 3. Explore (탐색)

| 항목 | 값 |
|------|-----|
| **모델** | Haiku |
| **도구** | 엄격한 읽기 전용 |
| **권한** | 읽기 전용 |
| **용도** | 빠른 코드 탐색 |
| **탐색 깊이** | Quick / Medium / Very thorough |

## 재개 가능한 서브에이전트

서브에이전트는 `agentId`와 `resume` 파라미터를 통해 이전 작업을 재개할 수 있습니다.

- 이전 서브에이전트의 세션 ID를 사용하여 작업을 이어서 진행 가능
- 긴 작업을 여러 단계로 나누어 수행할 때 유용

---

## 서브에이전트 제약사항

> **중요**: 서브에이전트는 다른 서브에이전트를 생성할 수 **없습니다**.

이 제한은 무한 중첩(Infinite Nesting)을 방지하기 위해 존재합니다. 서브에이전트는 1단계까지만 허용됩니다.

```
메인 대화 → 서브에이전트 (가능)
서브에이전트 → 또 다른 서브에이전트 (불가능)
```

## 실전 예시

### 코드 리뷰어

```markdown
---
name: code-reviewer
description: 코드 품질, 보안, 유지보수성을 검토하는 전문 코드 리뷰어. 코드 작성/수정 후 즉시 사용.
tools: Read, Grep, Glob, Bash
model: inherit
---

시니어 코드 리뷰어로서 높은 기준의 코드 품질과 보안을 보장합니다.

호출 시:
1. git diff 로 최근 변경사항 확인
2. 수정된 파일에 집중
3. 즉시 리뷰 시작

리뷰 체크리스트:
- 코드가 간단하고 읽기 쉬운지
- 함수와 변수의 명명이 적절한지
- 중복 코드가 없는지
- 적절한 에러 처리가 되어 있는지
- 노출된 시크릿이나 API 키가 없는지
- 입력값 검증이 구현되어 있는지
- 테스트 커버리지가 충분한지
- 성능 고려사항이 반영되었는지

피드백은 우선순위별로 정리:
- 치명적 이슈 (반드시 수정)
- 경고 (수정 권장)
- 제안 (개선 고려)

구체적인 수정 예시를 포함하세요.
```

### 디버거

```markdown
---
name: debugger
description: 에러, 테스트 실패, 예상치 못한 동작에 대한 디버깅 전문가. 문제 발생 시 적극적으로 사용.
tools: Read, Edit, Bash, Grep, Glob
---

근본 원인 분석에 특화된 전문 디버거입니다.

호출 시:
1. 에러 메시지와 스택 트레이스 수집
2. 재현 단계 파악
3. 실패 위치 격리
4. 최소 수정 사항 구현
5. 솔루션 검증

디버깅 프로세스:
- 에러 메시지와 로그 분석
- 최근 코드 변경사항 확인
- 가설 수립 및 테스트
- 전략적 디버그 로깅 추가
- 변수 상태 검사

각 이슈에 대해:
- 근본 원인 설명
- 진단을 뒷받침하는 증거
- 구체적인 코드 수정
- 테스트 방법
- 예방 권장사항

증상이 아닌 근본 원인을 수정하는 데 집중하세요.
```

### 보안 리뷰어

```markdown
---
name: security-reviewer
description: 코드 보안 취약점 분석 전문가. 보안에 민감한 코드 작성 후 즉시 사용.
tools: Read, Grep, Glob
model: opus
---

보안 전문가로서 코드의 보안 취약점을 분석합니다.

분석 항목:
- SQL 인젝션, XSS, CSRF 등 OWASP Top 10
- 인증/인가 취약점
- 데이터 유출 가능성
- 암호화 오용
- 입력값 검증 누락
- 세션 관리 이슈
- API 보안

각 발견 사항에 대해:
- 심각도 (Critical/High/Medium/Low)
- 취약점 설명
- 공격 시나리오
- 수정 권장사항
- 참고 자료
```

## 모범 사례

### 1. Claude로 초기 생성 후 반복 개선

처음에는 Claude를 통해 서브에이전트를 생성하고, 이를 개인화하며 발전시키세요. 이 방식이 가장 좋은 결과를 얻을 수 있습니다.

### 2. 단일 책임 원칙

한 가지 일만 하는 집중된 서브에이전트를 만드세요. 하나의 서브에이전트가 모든 것을 하려고 하면 성능과 예측 가능성이 떨어집니다.

### 3. 상세한 프롬프트 작성

구체적인 지침, 예시, 제약사항을 시스템 프롬프트에 포함하세요. 가이드가 명확할수록 성능이 향상됩니다.

### 4. 도구 접근 최소화

서브에이전트의 목적에 필요한 도구만 부여하세요. 보안이 강화되고 서브에이전트가 관련 작업에 집중할 수 있습니다.

### 5. 버전 관리

프로젝트 서브에이전트를 버전 관리에 체크인하세요. 팀 전체가 혜택을 받고 공동으로 개선할 수 있습니다.

### 서브에이전트 체이닝

복잡한 워크플로우의 경우 여러 서브에이전트를 연결할 수 있습니다.

```
> 먼저 code-analyzer 서브에이전트로 성능 이슈를 찾고, 
> 그 다음 optimizer 서브에이전트로 수정하세요
```

### 성능 고려사항

| 항목 | 설명 |
|------|------|
| **컨텍스트 효율성** | 서브에이전트는 메인 컨텍스트를 보존하여 더 긴 세션을 가능하게 함 |
| **지연 시간** | 서브에이전트는 매번 깨끗한 상태에서 시작하므로 필요한 컨텍스트를 수집하는 데 지연이 추가될 수 있음 |

---

## 요약

서브에이전트는 Claude Code의 강력한 기능으로, 특정 작업에 특화된 AI 어시스턴트를 통해 효율적인 문제 해결이 가능합니다. 명확한 역할 정의, 적절한 도구 제한, 상세한 프롬프트 작성이 핵심입니다.
